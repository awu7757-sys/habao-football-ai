## 4. 必修問題與建議方向

### R1｜熱門回算使用錯階段盤口
檔案：deploy/analysis-20261122/01_nba_confidence_and_direction_readonly.sql
fav CTE 每場優先取 T-2，沒有才取 T-15，再套用到所有階段。
影響：
- T-10 分組使用當時尚未知的盤口，屬前視資訊。
- T-15 分組也未必使用自己封存的盤口。
修正：
- T-10 使用自身快照盤口，依正式程式 primary 優先、有效性及一致性驗證後才退回 consensus。
- T-2／T-15 各取自己的 result_data 封存盤口。
- 缺少當階段資料標示無法判定，不向後補。

### R2｜交集命中率的下限不成立
「≤15/24（≥62.5%）」不正確。套交集可能移除贏或輸的紀錄。
修正：逐場套完整規則，列出確切保留、勝、負、走水；完成前標示「待回算」。

### R3｜回算母體不一致
兩份 SQL 未排除 late_pre_match_recovery；第5節後台卻只收 scheduled。
修正：正式比較統一只收 scheduled，補抓紀錄另區呈現；重跑兩份統計。
注意：不可把回算母體調整後的數字與舊 CSV 直接稱為同一批結果。

### R4｜前台會誤顯示暫不推薦原因
analysis.html 4317～4321行使用文字正則：
- 「與 T-10 方向相反」會顯示「與莊家方向相反」。
- 「盤口冷門」或「模型與盤口差距過大」會顯示「未取得盤口」。
修正：優先依 decision_code 顯示，舊快照再用既有文字備援。
因此規格「前台不需要改」必須修正。

### R5｜保留原始推薦，才能做上線後對照
僅存 model_pick／model_confidence 不足。新規則將 line 清為 null 後，舊規則仍須按原盤口結算。
修正：保留套用新規則前的完整推薦（pick、line、confidence、資格、reason），另存規則版本及正式輸出。
T-10 display_pick 是模型參考方向，不等於舊正式推薦；不可拿 display_pick 直接當舊規則。
對沒有完整基準的歷史快照，應標示不可比較，不可憑空補出正式推薦。

### R6｜T-10 基準要與未來執行一致
若最終選擇「T-10 沒推，後續也不推」，未來讀到的是已套新規則的 T-10。
歷史回算不能直接拿舊 T-10 推薦作比較，必須先算新規則的 T-10，再判斷 T-2／T-15。
若採本次建議允許 T-10 無推薦時後續獨立判斷，也需明定有推薦／無推薦／資料缺失的分支，保持回算與正式執行一致。

### R7｜現有 dry_run 不驗證推薦
nba-v2-stage-runner/index.ts 第542行 dry_run 只列候選，沒有執行 stageResult。
修正：增加離線固定資料測試或明確不寫入的純規則測試入口；不可把候選清單成功當規則測試通過。
不得為了測試覆寫舊 ready 快照或會員已領取結果。

## 7. 驗收清單

### 規則與邊界
- [ ] 主隊盤負／正／零／缺值／無效值。
- [ ] 主客盤線一致性；primary 有效才優先，否則按原規則退回。
- [ ] 原本暫不推薦者不因新規則變成推薦，且不產生新方向。
- [ ] T-10 有正式方向且同向／反向。
- [ ] T-10 無推薦／缺資料依最終核定策略處理。
- [ ] gap 在3、4.5、6邊界及兩側；用未取整差距判斷，避免顯示四捨五入改變資格。
- [ ] T-2／T-15 保留原45%～55%門檻的邊界語意（現行45%、55%本身可推）。
- [ ] 信心69／70及取整邊界按規格一致處理。
- [ ] 缺模型總分或盤口時不以0代替，也不因比較 null 而放行。
- [ ] 啟用日期之前／正好等於／之後；非法日期明確處理。
- [ ] 原始 pick、line、confidence 可完整追溯，歷史快照未改寫。

### 回算一致性
- [ ] 同一輸入由正式函式與後台回算得到相同 decision_code、pick、line。
- [ ] 規則函式無賽果輸入；賽果只在結算步驟使用。
- [ ] 各階段只使用當時封存資料，不補後續盤口或球員資訊。
- [ ] scheduled 與補抓分開；唯一賽事數與階段／玩法紀錄數分開。
- [ ] 勝、負、走水、無推薦、缺資料及分母明確；若有四分之一盤，使用一致拆盤結算，現有 SQL 的單次 sign 判定不能直接涵蓋半贏半輸。
- [ ] 新規則交集有逐場明細，可確認被移除的是贏或輸。
- [ ] 舊／新／挑戰使用相同賽事範圍與有效資料條件。

### 前台與部署
- [ ] 單場、批次、免費重看讀同一正式快照。
- [ ] 暫不推薦與原因標籤正確，沒有顯示 qualified 或誤指盤口缺失。
- [ ] 管理員驗證保留，共用檔隨三函式部署且版本一致。
- [ ] 測試有真正執行規則，不只是現有 dry_run 候選查詢。
