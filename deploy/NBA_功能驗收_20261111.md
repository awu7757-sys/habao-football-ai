## 本次修正

1. 同一個讓分盤，V1／V2 選擇不同隊時，改用主隊基準盤口比較，避免誤排除有效同場樣本。
2. 比較頁快速切換日期時只顯示最後一次請求；HTTP 200 但資料不完整時顯示錯誤，避免誤顯示零場。
3. 管理員授權服務暫時故障回傳 500，避免誤當登入過期。
4. NBA 今日／明日較舊的請求不再覆蓋最新列表，也不會覆蓋已切換的其他運動。
5. 單場 NBA 連點防重複請求；單場與批次互斥；不完整或錯場的回應不進入結果列表。
6. V2 供應商暫時錯誤保存為 source_error，讓後續排程可以重試；真正缺少統計才使用原有得失分備援。
7. 驗證 Box 快取的隊伍與數值；損壞快取重新取得，避免產生無效模型。
8. 處理逾時重取工作時，用 updated_at 核對工作持有者，避免舊工作覆寫新工作。
9. 缺少／格式錯誤的歷史 API 回應不再當成正常空資料；排除其他聯盟、無效比賽 ID。

模型仍為 nba-v2-unified-efficiency-shrinkage-v0.2；沒有調整權重、研究推薦門檻或增加 T-2／T-15。

## SQL 之後需要的實場流程

1. 核對 V1 快照唯一、賽前時間、V2 來源時間、研究表權限、重試狀態與統合 V2 排程。
2. 測試會員選一場已進入 T-10 的未開賽賽事：記錄額度 → 首次取得 → 重看 → 連點／兩分頁，核對資料庫是否只扣一次。前端防連點不能取代後端原子扣點驗證。
3. 批次測試成功、部分失敗、額度不足、停權與恢復；核對成功場數、扣點與歷史。
4. 同場核對後台 V1／V2 顯示，V1 正式與 V2 研究不得混用；V2 source_error 須確認排程實際重試。
5. 完賽後核對官方比分、原始盤口結算、會員結果與公開紀錄；推播需用已訂閱的測試裝置實際確認。
6. Cron 的 succeeded 只代表 SQL 呼叫成功，還須看 Edge Function 回應與資料落地；HTTP 200 也可能包含 source_error 或 processed=0。

若某項無符合條件的實際賽事，標示待實場，不寫成通過。
