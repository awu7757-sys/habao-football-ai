# 規格草案：VIP 每週投注分配工具（2026-11-22，待審查、尚未實作）

狀態：使用者與 Claude 討論中的草案，**尚未決定、尚未寫程式**。請審查者只審查與建議。

## 1. 定位

- 只給 VIP，入口在「我的分析」。是「工具」，不保證獲利；頁面註明「投注有賺有賠，分配結果僅供參考」。
- 資料只存在會員自己的裝置（瀏覽器），頁面寫「您的資料是保密的，HB 無法查看」，因此**不得把會員輸入的金額或收支送到後端**。
- 搭配「每月預算計算器」（收入 − 支出 = 可支配所得，不給建議上限），會員自行決定撥多少當娛樂金。

## 2. 以一週為單位

- 每週一設定本週娛樂金 W。
- 每天可用金額 D = 本週剩餘金額 ÷ 本週剩餘天數（未用完滾入後續；輸多則後續自動縮小）。〔待決定：或固定 W/7〕
- 週報：注數、總投入、實際賺賠、投報率；分球類、分玩法；並顯示「若本週用平均分配」的對照結果。
- 輸了不自動加碼（禁止倍投）。

## 3. 選場與分配方式

- 「投注分配」按鈕：導入今日全部分析，或勾選部分場次。
- 三種方式：平均分配（D ÷ 場數，預設）、AI 分配（第 4 節）、自填。

## 4. AI 分配算法（草案）

對每一筆推薦（某場 × 某玩法）：

1. **估計勝率**（向整體命中率收縮，避免小樣本）：
   `p = (聯賽該玩法命中數 + K × 整體命中率) / (聯賽該玩法場數 + K)`，K = 20。
   - 整體命中率＝同球類、同玩法（必要時同階段）的歷史命中率。半贏計 0.5、走盤不計。
   - NBA 只有一個聯賽：改用「玩法 × 信心區間」分組。
2. **期望值**：`EV = p × 賠率 − 1`（十進位賠率）。
3. **凱利比例**：`f = EV / (賠率 − 1)`，取 **1/4 凱利**：`f' = f / 4`。
4. **分配**：當日 f' > 0 的場次按 f' 比例分配 D；單場上限 25% × D；金額取整到 10 元。
   - EV ≤ 0：給最低金額（例如 D 的 5%）或排除〔待決定，會員可切換〕。
5. 例（D = 1,000）：A NBA 獨贏 賠率 1.45、p 0.70 → EV +1.5%、f'≈0.008；B 足球讓分 賠率 1.95、p 0.55 → EV +7.3%、f'≈0.019；C 大小 賠率 1.90、p 0.50 → EV −5% → 最低 100；A、B 依比例分剩餘 900 → 約 270／630。

## 5. 賠率來源

- 有市場賠率的自動帶入，會員可改成自己投注平台的賠率；沒有的由會員手填。
- 目前可用：足球 T-10 獨贏／讓分／大小（`match-analysis` market_odds，Odds API h2h/spreads/totals）；足球 T-2／T-15 讓分／大小（`market_context`）；NBA T-10 讓分／大小（獨贏待確認）；NBA T-2／T-15 讓分／大小（`nba-v2-stage-runner` 只抓 spreads,totals）。BTTS 無市場賠率。
- 存的是分析當下賠率，會員下注時可能已變動，預設請會員確認。
- 〔待決定〕是否讓系統另抓獨贏賠率（The Odds API 用量約 +50%）。

## 6. 需要的後端

- 「聯賽 × 玩法（× 階段）」命中率的唯讀端點（目前公開戰績只有球類 × 玩法）。依專案規則，後端由使用者依指示部署。

## 7. 已知限制

- 「命中率高 ≠ 獲利」：獲利取決於命中率與賠率；應以投報率評估。
- 聯賽 × 玩法樣本小，K = 20 收縮只能部分緩解。
- 一週結果受運氣影響大，週報應呈現為「本週結果」，不代表長期表現。
- 法規：直接建議每場金額接近投注顧問性質，上線前宜由熟悉台灣法規者確認（非法律意見）。
